# rkv — 基于 Rust 的可持久化网络键值存储系统

高级系统编程技术课程设计。系统由**服务器程序**和**命令行客户端**组成，
支持键值数据的写入、查询、修改、删除，支持多客户端并发访问，
服务器重启后数据不丢失。仅依赖 Rust 标准库，无第三方依赖。

## 快速开始

```bash
cargo build --release          # 构建
cargo test                     # 运行全部单元测试与集成测试

# 终端 1：启动服务器
cargo run --bin rkv-server -- --addr 127.0.0.1:7878 --data data/rkv.log

# 终端 2、3……：启动多个客户端
cargo run --bin rkv-client -- --addr 127.0.0.1:7878
```

启动参数均可省略，默认监听 `127.0.0.1:7878`，数据文件为 `data/rkv.log`
（目录与文件不存在时自动创建，以空数据库启动）。

## 客户端命令

| 命令 | 说明 | 成功响应 |
| --- | --- | --- |
| `SET <键> <值>` | 写入或覆盖 | `OK` |
| `SETEX <键> <秒> <值>` | 写入并设置过期时间（扩展） | `OK` |
| `GET <键>` | 查询 | `VALUE <值>` / `NOT_FOUND` |
| `DEL <键>` | 删除 | `OK` / `NOT_FOUND` |
| `LIST` | 列出全部键（升序） | `KEYS k1 k2 ...` |
| `STATS` | 键数量、在线连接数、运行时长 | `STATS keys=.. clients=.. uptime_secs=..` |
| `PING` | 连通性检查 | `PONG` |
| `COMPACT` | 压缩数据文件（扩展） | `OK` |
| `HELP` | 客户端本地帮助 | — |
| `QUIT` | 断开连接 | `BYE` |

约定：键不含空白字符、不超过 256 字节；值不含换行、不超过 4 KB；
单条消息不超过 8 KB。任何非法输入都会返回 `ERR <原因>`，连接不中断。

演示示例：

```
rkv> SET 课程名称 Rust程序设计
OK
rkv> GET 课程名称
Rust程序设计
rkv> STATS
键数量: 1  在线连接: 2  运行时长: 35s
（重启服务器后）
rkv> GET 课程名称
Rust程序设计
```

## 模块划分

```
src/
├── lib.rs        模块声明
├── error.rs      统一错误类型（IO / 协议 / 数据损坏）
├── config.rs     命令行参数解析
├── protocol.rs   命令模型与文本协议（客户端与服务器共用）
├── store.rs      运行时内存数据管理（BTreeMap + 过期时间）
├── persist.rs    追加写日志、启动恢复、日志压缩
├── engine.rs     组合 store 与 persist，执行一条命令
├── server.rs     TCP 监听、连接线程、共享锁
└── bin/
    ├── server.rs 服务器入口
    └── client.rs 交互式客户端入口
```

依赖方向自上而下单向：`bin → server → engine → {store, persist} → {protocol, error}`。

## 关键设计

**协议**：一行一条消息，以 `\n` 为边界，UTF-8 文本。文本协议便于人工调试和演示，
客户端与服务器共用 `protocol` 模块，避免双方理解不一致。

**持久化**：采用追加写日志（append-only log），每次成功的写操作先追加一行记录、
`fsync` 落盘，然后才更新内存并返回 `OK`，因此客户端收到成功时数据一定已可靠保存。
启动时按写入顺序重放全部记录，得到上次运行结束时的最终状态。
记录格式为 `SET\t<键>\t<过期时间|->\t<值>` 与 `DEL\t<键>`，键值中的
`\`、`\t`、`\n`、`\r` 会被转义，保证一条记录不跨行。

**异常处理**：文件格式非法、末尾记录被截断（上次写入中途崩溃）都会在启动时
明确报错并拒绝启动，绝不静默清空数据；`COMPACT` 采用「写临时文件 + 原子重命名」，
中途失败不会破坏原文件。

**并发**：每个连接由独立线程处理，通过 `Arc<Mutex<Engine>>` 共享同一份数据。
互斥锁只在执行一次数据操作期间持有，等待网络输入或发送响应时不持锁，
避免慢客户端阻塞其他连接；单个连接的错误被隔离在自身线程内，不影响服务器整体。

**扩展功能**：`SETEX` 过期时间（绝对时间戳，重启后语义仍正确，惰性删除）、
`COMPACT` 日志压缩、`STATS` 在线连接统计。

## 测试

- 单元测试（23 项）：参数解析、协议解析与编解码往返、内存增删改查与过期、
  日志记录往返、重启恢复、损坏与截断检测、压缩、引擎命令执行。
- 集成测试（8 项，`tests/integration.rs`）：真实 TCP 连接下的完整流程、
  错误命令后连接可用、超长与非 UTF-8 输入、8 客户端并发写入 160 键、
  重启恢复、过期生效、压缩、损坏文件拒绝启动。

```bash
cargo test              # 全部测试
cargo clippy --all-targets   # 静态检查
```
